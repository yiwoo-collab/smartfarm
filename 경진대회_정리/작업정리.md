# 모바일 스마트팜 앱 v3.0 — 작업 정리 (2026-11-18 경진대회 기준)

캡스톤 디자인 프로젝트. 저장소: https://github.com/yiwoo-collab/smartfarm (main, 마지막 커밋 `ad37bc3`)

## 1. 한 줄 요약
교수님이 제공한 산업용 원격 감시 장비(RMU)에 센서를 모두 연결하고, 라즈베리파이가 RMU를 SNMP로 조회·Trap 수신해 위험 등급을 판단한 뒤, 핸드폰 앱(Flutter)으로 보여 주고 제어하는 **인터넷 없이 현장에서 동작하는 스마트팜 감시 시스템**.

## 2. 최종 구성 (경진대회 당일)

| 장비 | 주소 | 역할 |
|---|---|---|
| NEXTU 공유기 | 192.168.0.1 | 내부망 (인터넷 연결 없음) |
| RMU (PowerLine RMU5G) | 192.168.0.50 (DHCP 예약, 커뮤니티 public) | 센서 수집, SNMP Get/Set/Trap |
| 라즈베리파이 4B | 192.168.0.10 (고정, 사용자 smartfarmpi, 코드 ~/smartfarm) | 게이트웨이: 5초 조회, 등급 판단, AI, REST API(8080), SQLite 기록 |
| 핸드폰 앱 v3.0 | 공유기 Wi-Fi | 라즈베리파이 REST에만 접속 |
| 노트북 | Wi-Fi=외부 인터넷, 랜선=NEXTU | 관리·실시간 모니터 화면 |

센서 (전부 RMU 단자): TMP1 온도, TMP2 토양 온도, HUMI 습도, FIRE 화재 감지기, FLOOD 수위 플로트. 전원(acv1/ach1)은 RMU 자체 측정.
라즈베리파이는 systemd 서비스 `smartfarm-rmu`로 부팅 시 자동 실행 (`server.py --hardware --rmu-host 192.168.0.50`).

## 4. 핵심 구현
- **SNMP v2c 직접 구현** (`rmu/snmp_lite.py`, 표준 라이브러리만): Get·GetNext·Set·Trap 인코딩/디코딩.
- **oids.json 단일 출처**: OID·scale·offset·`fault_raw_max`를 한 파일에서 관리 → 코드에 OID 번호 없음.
- **상태 구분**: 정보없음(noSuchObject/센서 없음) / 센서 오류(비정상 값) / 통신 두절(마지막 수신 시각). 값이 없으면 0이나 이전 값으로 채우지 않음.
- **3단계 등급**: 주의·경보·긴급. RMU는 알람 코드만 주므로 등급은 라즈베리파이가 계산.
- **자동 제어**: 고온·저온 단계별 조치, 긴급 시 해결 장비만 유지, 환풍기 이중화(메인 고장 → 예비), 야간 모드, 화재 시 열원·전기·환기 정지.
- **설명 가능한 AI**: 온도 상승 속도로 상한 도달 전 선가동하고 이유 표시 ("0.15℃/분, 약 69분 뒤 상한"). 실사용 모드는 위험 낮은 조치만 자동, 나머지는 승인. allow-list, 시간당 10회 제한, 수동 우선, 전부 로그.
- **앱 데모 모드**: `demo_rmu.dart`가 서버 규칙(rmu_model.py)을 그대로 옮겨 하드웨어 없이 29개 시나리오 재현.
- **테스트**: Python 56개, Flutter 40개 통과 (11-17 기준).

## 5. 실물 장비에서 찾아 고친 문제 (발표·포트폴리오 소재)
1. RMU가 LCD에 표시된 IP로 응답하지 않음 → 실제 이더넷은 DHCP 주소 사용. 공유기 기록과 MAC으로 찾아냄.
2. 온도 센서를 빼면 −30℃로 읽혀 저온 오경보 → raw ≤ 200을 센서 오류로 구분.
3. 감지기 없는 도어 단자가 '열림'으로 읽혀 경보 → 정보없음 처리.
4. 수위 플로트는 0/100%만 나옴 → 정상/부족 표시, 하락 속도로 하는 누수 판단은 데모 모드만.
5. 예전 기록 DB 형식 때문에 서버 갱신 루프가 멈춤 → 수정 (`945cd9c`).
6. 라즈베리파이 시계가 UTC여서 야간 모드 오작동 → Asia/Seoul. RTC가 없어 오프라인에서는 시계를 노트북에서 맞춤.
7. Windows에서 만든 서비스 파일의 CRLF 줄바꿈 → `.gitattributes`로 LF 강제.

## 6. 경진대회 당일 관찰 → 다음에 할 일
- RMU **addTrap 등록이 비어 있는 것**을 확인함 (서비스는 정상). Trap 재등록 로직 점검 필요. 경보는 5초 조회로 정상 동작했음.
- 습도가 50% 기준선 근처에서 경보와 복구가 몇 분마다 반복됨 → **히스테리시스** 추가.
- 화재 감지기는 한 번 감지하면 유지되는 래치 방식이라 커넥터를 뺐다 꽂아야 리셋됨.
- 홈 화면 화재 칸은 누를 수 없음 (그래프가 없어서). 알림 탭의 화재 기록으로 연결하면 좋음.
- 노트북용 실시간 모니터는 이 폴더의 `스마트팜_실시간_모니터.html`로 저장소에 넣었음.
- 그 밖에 남은 것: admin.json(현재 개발용 관리자 계정), 앱이 꺼져 있을 때 받는 푸시, 실제 장비 제어(릴레이), 토양 온도 기준값, 11장 미확정 사항.

## 7. 노트북 실시간 모니터 (`스마트팜_실시간_모니터.html`)
- 라즈베리파이와 같은 공유기에 연결된 PC에서 파일을 더블클릭하면 브라우저에서 열립니다. 설치할 것은 없습니다.
- 2초마다 라즈베리파이 REST API(`/api/status`, `/api/events`)를 읽어 경보 배너, 센서 칸(정상/센서 오류/정보없음), 온도·습도 그래프, AI 판단 이유, 장비 상태, 최근 알림·조치 내역을 보여 줍니다.
- 라즈베리파이 주소는 오른쪽 위 입력칸에서 바꿀 수 있습니다 (기본 `192.168.0.10:8080`). F11을 누르면 전체 화면이 됩니다.
- 부스 모니터 화면용으로 경진대회 당일 만들었습니다.
